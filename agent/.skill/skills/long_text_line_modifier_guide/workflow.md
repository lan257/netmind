# 长文本分块文件编辑流程

1. 先用 `line_reader` 读取目标文件的相关行，确认文件已存在、目标锚点、原始行号和当前总行数。
2. 判断长文本属于哪种修改：替换已有大段内容、在文件尾部分段追加、在局部插入较长内容，或分散修改多个互不影响的区域。
3. 把待写入内容按语义边界拆块，优先在段落、标题、函数、列表项或配置块边界处分割；每个 `line_modifier` 调用的目标范围不超过 40 行，新内容不超过 40 行且 `new_content` 不超过 4000 字符。
4. 为每个块准备独立的 `filepath`、`start_line`、`end_line` 和 `new_content`。`new_content` 放进 Tool 参数时必须保持合法 JSON 字符串，换行、双引号和反斜杠按 JSON 规则转义。
5. 行号能稳定推算时，在同一轮 `tool_call_drafts` 中按执行顺序请求多个 `line_modifier` 调用，不要把长文本塞进一个超限调用。
6. 替换多个已有行段时，优先从文件底部向顶部提交块，避免较早的插入或删除改变尚未修改区域的原始行号。
7. 在文件尾部追加长文本时，先用当前总行数确定第一块的 `start_line=end_line=总行数+1`；同批后续块必须按前面块的预计写入行数累加出新的尾部行号，保证每次仍追加到新的文件末尾。
8. 如果某个块会在后续目标行之前插入或删除行，而后续行号无法可靠累计，先执行当前批次，再用 `line_reader` 重读后续锚点后继续下一批。
9. 批量调用返回后，用 `line_reader` 校验受影响区域是否完整、顺序是否正确、边界是否被截断；只重试失败或错位的块。
10. 遇到行数、字符数或行号漂移错误时继续拆小块并重算行号，不要仅因为文本很长改用整文件覆盖类 Tool。
